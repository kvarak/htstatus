# DOC-034: Get "Player details and progress" approved

CHPP denied this function in [FunctionalDescription.md](../FunctionalDescription.md) (copied from Hattrick, don't edit it). No approved function lists Players or PlayerDetails, but every Update calls both (`chpp.team()` → `players`, `chpp.player()` → `playerdetails` in `app/blueprints/team.py`). That breaks license rule 4.1 (see `docs/CHPP-ENFORCEMENT.md`).

## Likely reasons (check the denial message on the product page first)

- **Wrong files:** it lists Players and RegionDetails. The code uses Players and PlayerDetails and never calls RegionDetails.
- **Too much in one function:** player data, training progress, the formation tester, team stats and transfer bids together. The formation tester and team stats download nothing.
- **"Bids on transfer-listed players"** can read like scouting the transfer market or bidding. It only means the user's own listed players: the asking price, highest bid and deadline that playerdetails gives the owner.

## Resubmission (ready to paste)

Title: **Players and their progress**

Description:

> The players of the user's own team(s), as Hattrick shows them to the owner: skills, form, stamina, TSI, salary, specialty, personality, loyalty, injuries, cards and goals. Each "Update data" stores a snapshot, so the user sees what changed since the previous update and how each player progressed over time. For the user's own transfer-listed players we also show asking price, highest bid and deadline. Read only (no bids are placed), and fetched only when the user clicks "Update data".

Xml files: **Players, PlayerDetails**

This matches the code: `chpp.team()` reads `players` (the skills and the basic fields), and `chpp.player()` reads `playerdetails` (salary, TSI, goals, caps, mother club bonus and the transfer bid via `app/transfers.py`). The formation tester and team stats only use stored data, so they are left out.

If it is denied again, ask the CHPP admins why, or add Players and PlayerDetails to the approved "Overview of team and progression" function.

Open question: `chpp.player()` asks for `includeMatchInfo=true`, but nothing reads the LastMatch data. The comment says the goal fields need it, while `docs/chpp/api-reference-playerdetails.md` says it only adds LastMatch. Check the XML on the next real Update. If the goals are there without it, drop the parameter ("minimum data", license 5.4).
