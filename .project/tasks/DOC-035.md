# DOC-035: Get "Training log and cycle planner" approved

CHPP denied this function in [FunctionalDescription.md](../FunctionalDescription.md) (copied from Hattrick, don't edit it). Every Update still calls `training` (`app/training_log.py`), and no approved function covers it. That breaks license rule 4.1 (see `docs/CHPP-ENFORCEMENT.md`).

## Likely reasons (check the denial message on the product page first)

- **StaffList is listed but not used.** It is only planned (FEAT-044). Functions should list the files the product uses now.
- **"Training speed per player"** can sound like the app works out hidden game mechanics (sub-skills, exact formulas). What the app does is count the weeks between the skill changes the user saw in their own players (`app/training_speed.py`).
- **"Multi-season training plans"** isn't built yet (FEAT-038 to FEAT-040). It can also sound like the app sets training, which would need the `set_training` scope the app doesn't ask for.
- **Admin speed overview** (`app/training_speed_stats.py`) pools training speeds from all users' teams. If the CHPP admins see that as using one user's data for others (license 5.2), keep it out of the product or ask first.

## Resubmission (ready to paste)

Title: **Training log**

Description:

> A weekly log of the user's own team's training as Hattrick reports it: training type, intensity, stamina share and trainer. Combined with the minutes the user's players played (from match lineups), it shows who was trained each week, and from the skill changes the user has seen in their own players, how many weeks each skill level took. Read only (training is never set from here), and fetched only when the user clicks "Update data".

Optional last sentence (recommended, to be open about the admin speed overview):

> The site admin can see an anonymous summary of these training weeks across all teams, used to improve the estimates; it is never shown to other users.

Xml files: **Training**

This matches the code:
- `chpp.training()` reads `training` (this week's and last week's type, intensity and stamina share, and the trainer) in `app/training_log.py`.
- "Who was trained" (`app/trainees.py`) and the measured speed (`app/training_speed.py`) use stored data only. The minutes come from MatchLineup, which the approved "Matches" function already covers.
- StaffList is left out until FEAT-044 uses it.

Later, when they are built:
- **Training plan (FEAT-038 to FEAT-040):** submit as a separate function. Plans stay in HattrickPlanner and are never sent to Hattrick, so no new XML file is needed.
- **Coaching staff (FEAT-044):** add StaffList, either to this function or as its own function.

If it is denied again, ask the CHPP admins why. If the pooled admin overview is the problem, limit `app/training_speed_stats.py` to the admin's own teams.
